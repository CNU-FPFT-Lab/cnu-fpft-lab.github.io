2. 기본 수정·저장 절차

  1. https://cnu-fpft-lab.github.io/manage/에 접속해 GitHub로 로그인합니다.
  2. 왼쪽 메뉴에서 수정할 데이터 종류를 선택합니다.
  3. 필드를 수정하고 이미지가 필요하면 기본 미디어 선택기를 사용합니다.
  4. 저장 전 ID, 제목, 날짜, 이미지가 의도대로 들어갔는지 확인합니다.
  5. 편집 화면 상단의 Decap 저장/발행 버튼으로 확정합니다.
  6. GitHub Pages 배포 후 홈페이지에서 최종 확인합니다.
저장 버튼이 비활성화되어 있으면 실제 데이터 값이 바뀌지 않은 상태일 수 있습니다. 특히 이미지는 미디어 창에서 ‘선택한 것으로 결정’까지 해야 필드 변경으로 인식됩니다.

3. 구성원 관리

PI

이름, 영문명, 직위, 이메일, 전화, 교수실, 소개, 프로필 사진을 관리합니다. 프로필은 세로 사진을 권장하며 홈페이지에서 정해진 프레임에 자동 맞춤됩니다.

학생

이름, 영문명, 과정, 이메일, 프로필 사진을 관리합니다. 과정 값은 CMS에 지정된 선택값을 사용하는 것이 안전합니다.

기존 학생을 수정할 때는 다른 학생 행을 삭제하지 않도록 주의합니다. 큰 구조 수정 전에 현재 내용을 한 번 확인한 뒤 저장하세요.

4. Research 관리

ID페이지 식별에 사용됩니다. processing, foodtech 같은 기존 ID는 특별한 이유가 없으면 변경하지 않습니다.
번호현재 Research 01 / 02 구조와 맞게 유지합니다.
대표 인포그래픽가로 약 1500 px 이상 원본 권장. PNG/JPG/WebP 등을 올리면 홈페이지가 화면 크기에 맞춰 자동 축소합니다.
연구 흐름단계 순서를 바꾸면 Research 페이지의 흐름 표현도 바뀔 수 있으므로 저장 전 순서를 다시 확인합니다.
세부 연구주제 Figure원본 비율을 유지하도록 설계되어 있으므로 불필요하게 저해상도로 줄이지 않습니다.
메인화면 Research 01+02: 두 Research 인포그래픽을 한 화면에 함께 보이도록 구성한 PPT 원본을 별도로 보관하고, 홈페이지에서는 같은 두 패널을 고해상도·반응형으로 표시합니다.

5. 이미지 교체 절차

  1. 이미지 필드를 눌러 Decap의 이미지 창을 엽니다.
  2. 새 원본 파일을 업로드합니다.
  3. 목록에 나타난 새 이미지 썸네일을 클릭합니다.
  4. 초록색 ‘선택한 것으로 결정’을 누릅니다.
  5. 편집 화면으로 돌아왔을 때 이미지 필드가 새 파일로 바뀌었는지 확인합니다.
  6. Decap의 저장/발행 버튼을 눌러 GitHub에 반영합니다.
미디어 창의 ‘다운로드’, ‘이름 복사’, ‘선택항목 삭제’는 일반적인 이미지 교체 과정에서는 사용하지 않습니다. 기존 파일 삭제는 해당 파일을 쓰는 다른 페이지까지 영향을 줄 수 있습니다.

6. 교수·학생 계정 권한 관리

OAuth Worker 소스는 교수용과 학생용 역할을 구분하도록 구성되어 있습니다. 현재 저장소 설정에서 교수 관리자 username은 dkrnd2로 지정되어 있고, 학생 username은 별도 허용목록에 쉼표로 추가하도록 되어 있습니다.

MANAGER_GITHUB_USERS = "dkrnd2"
STUDENT_GITHUB_USERS = "student-a,student-b"

학생 추가·삭제로 Worker 설정을 바꾼 뒤에는 Cloudflare Worker를 최신 소스로 다시 배포해야 실제 로그인 제한에 적용됩니다.

학생에게는 저장소의 필요한 편집 권한만 부여하고, 관리자 권한은 부여하지 않는 것을 권장합니다.

7. 잘못 저장했을 때 복구

  1. 문제를 발견하면 같은 화면에서 여러 차례 추가 저장하지 않습니다.
  2. GitHub 저장소의 최근 commit history에서 어떤 파일이 바뀌었는지 확인합니다.
  3. 문제 직전 정상 커밋의 내용을 기준으로 해당 JSON/HTML을 복원합니다.
  4. 복구 후 Pages 배포가 완료되면 Ctrl+F5로 실제 사이트를 확인합니다.

CMS의 각 저장은 GitHub 커밋으로 남으므로 대부분의 콘텐츠 실수는 이전 버전에서 복구할 수 있습니다.

8. 배포·캐시 확인

저장 직후 홈페이지가 즉시 바뀌지 않을 수 있습니다. GitHub Pages 배포가 완료될 때까지 수십 초 정도 기다린 뒤 확인합니다. Chrome에서 이전 버전이 보이면 Ctrl + F5를 사용합니다.

저장 전 최종 체크

① 수정할 항목이 맞는지 → ② 기존 항목을 실수로 삭제하지 않았는지 → ③ 이미지 선택이 실제 필드에 반영됐는지 → ④ Research ID를 불필요하게 바꾸지 않았는지 → ⑤ 저장 후 실제 사이트를 확인했는지 순서로 점검합니다.
