구성원·PI 정보와 Research 구조는 학생용 /admin/ 편집 화면에서 제외되어 있습니다. 그러나 GitHub 저장소에 Write 권한이 있으면 GitHub 웹사이트에서 다른 코드·데이터 파일을 직접 고칠 수도 있습니다. 이는 CMS의 메뉴 제한일 뿐 저장소 전체의 파일별 보안 차단은 아닙니다. 반드시 허가된 네 가지 콘텐츠만 편집하세요. 현재 학생 수정은 교수 승인 후 게시 방식이 아니며, 저장 시 바로 main 브랜치에 반영될 수 있습니다.
학생용 CMS 허용공지사항·논문·연구실 활동/대표사진·연구과제 항목의 추가·수정·삭제
학생용 CMS 미노출PI/학생 구성원, Research 01·02 구조와 인포그래픽, 홈페이지 HTML·CSS·JS
계정·보안 설정다른 관리자 추가, 교수 계정 승격, Cloudflare Worker 재배포, GitHub 권한 변경은 학생에게 맡기지 않습니다.
GitHub Write 권한의 실제 범위저장소에 별도 브랜치 보호가 없다면 CMS 밖에서 다른 파일을 변경할 수 있습니다. 교수님 승인 없는 직접 코드 수정은 금지하는 운영 규칙을 적용합니다.

최초 계정 등록 시 확인할 사항

  1. 본인의 GitHub 계정으로 로그인한 뒤 프로필 화면의 URL에서 username을 확인합니다. 예: github.com/사용자명. 이메일 주소와 username은 다를 수 있습니다.
  2. 확인한 username 또는 GitHub 프로필 링크를 교수님께 전달합니다. 비밀번호는 전달하지 않습니다.
  3. 교수님이 저장소 Write 초대를 보내면 해당 GitHub 계정으로 초대를 수락합니다.
  4. 교수님이 Cloudflare Worker의 STUDENT_GITHUB_USERS에 정확한 username을 등록하고 재배포한 뒤에 학생용 편집기에 로그인합니다.
저장소 초대 수락만으로는 로그인되지 않을 수 있습니다. GitHub 쓰기 권한과 CMS 허용목록 등록 두 조건을 모두 확인하세요.

1. 로그인

  1. https://cnu-fpft-lab.github.io/admin/에 접속합니다.
  2. Login with GitHub를 선택하고 허용된 GitHub 계정으로 로그인합니다.
  3. 왼쪽 메뉴에서 수정할 항목을 선택합니다.

로그인이 거부되면 GitHub 초대 수락·저장소 Write 권한·학생 허용목록·Worker 재배포 여부를 교수님께 확인받습니다. 비밀번호·토큰 공유는 필요하지 않습니다.

2. 내용 수정과 저장

  1. 왼쪽에서 공지사항 / 논문 / 연구실 활동·사진 / 연구과제 중 하나를 엽니다.
  2. 수정할 항목을 펼쳐 필요한 필드만 변경합니다.
  3. 입력이 끝나면 편집 화면 상단의 Decap 저장 또는 발행 버튼을 누릅니다.
  4. 저장 완료 메시지가 나온 뒤 홈페이지 배포가 끝날 때까지 잠시 기다립니다.
중요: 이미지 선택 창에서 ‘선택한 것으로 결정’을 누르는 것은 이미지 필드에 적용하는 단계입니다. 홈페이지에 최종 저장하려면 다시 편집 화면에서 저장/발행을 눌러야 합니다.

3. 사진·이미지 업로드

  1. 수정하려는 이미지 필드를 클릭해 Decap의 ‘이미지’ 창을 엽니다.
  2. 업로드 버튼 또는 파일 선택 기능으로 컴퓨터의 원본 파일을 올립니다.
  3. 업로드된 이미지의 썸네일을 한 번 클릭해 선택 상태로 만듭니다.
  4. 오른쪽의 초록색 ‘선택한 것으로 결정’ 버튼을 누릅니다.
  5. 이미지 창이 닫힌 뒤 편집 화면의 이미지 필드가 새 사진으로 바뀌었는지 확인합니다.
  6. 마지막으로 편집 화면의 저장/발행 버튼을 누릅니다.
주의: ‘다운로드’, ‘이름 복사’, ‘선택항목 삭제’는 이미지 교체에 필요한 버튼이 아닙니다. 특히 ‘선택항목 삭제’는 기존 파일을 지울 수 있으므로 사용하지 마세요.

4. 저장 후 반영 확인

  1. 저장 후 보통 수십 초 정도 GitHub Pages 배포 시간이 필요합니다.
  2. 홈페이지를 새로 열어 변경사항을 확인합니다.
  3. 이전 내용이 계속 보이면 Windows Chrome 기준 Ctrl + F5로 강력 새로고침합니다.
한 번 저장했다면 배포 중에 같은 내용을 여러 번 반복 저장하지 않는 것이 좋습니다.

5. 문제 해결

저장 버튼이 활성화되지 않음실제 필드 값이 변경되지 않았을 가능성이 큽니다. 이미지라면 썸네일 선택 → ‘선택한 것으로 결정’까지 완료했는지 확인합니다.
새 사진이 안 보임배포를 잠시 기다린 뒤 Ctrl+F5를 실행합니다.
GitHub 로그인 거부GitHub username이 학생 허용목록에 등록되어 있는지 확인합니다.
잘못된 항목을 삭제함추가 저장을 반복하지 말고 바로 교수님에게 알립니다. GitHub 이전 커밋에서 복구할 수 있습니다.

6. 학생 운영 원칙

자신이 담당하는 공개 콘텐츠만 /admin/에서 수정합니다. 기존 다른 기록의 삭제·ID 변경·JSON 직접 편집은 하지 않습니다. manage/, oauth-proxy/, data/members.json, data/research.json, HTML·CSS·JS 파일은 GitHub에서 직접 수정하지 않습니다. 구성원·Research 변경은 교수님께 요청합니다.

계정 비밀번호와 OAuth 토큰을 공유하지 않고 2단계 인증을 설정합니다. 담당 종료 시 저장소 쓰기 권한과 학생 허용목록을 함께 회수합니다.
